旧查询对中文词生成最多 24 个前后通配符并使用模糊匹配；新查询使用分词匹配和标题短语加权，不对中文和长查询做模糊扩展。单个 3～24 位英文或数字词保留一个有界通配符与受限模糊匹配：`coffe` 样例返回 53 条，ES took 为 600 ms，与旧查询的 53 条相同。短英文首字符错误和多词内部子串的召回可能变化，需要固定标注集继续评测。

基于服务器正在使用的旧版制品构造的隔离后端预览中，长标题请求的关键词通道成功、耗时 79 ms，目标内容在融合结果中排第 2。预览因服务器 Redis 要求认证而关闭了 Redis 健康检查，实时特征状态为 `UNAVAILABLE`，因此这不是完整线上验收；正式后端仍运行旧检索代码。

对照使用以下结构化查询骨架，实际字段和条件以 `ElasticsearchSearchAdapter.keywordSearchBody` 为准：

```json
{
  "query": {
    "bool": {
      "should": [
        {"multi_match": {"query": "用户查询", "type": "best_fields", "fields": ["title^5", "tags^4", "summary^3", "description^2", "body^2", "transcript"]}},
        {"match_phrase": {"title": {"query": "用户查询", "boost": 8}}}
      ],
      "minimum_should_match": 1
    }
  }
}
```

不能根据少量样例声称 Recall@K 提升。正式效果结论仍需覆盖短词、长句、多语言、错拼、标签过滤和无结果查询的固定标注集，并记录延迟分位数与降级率。
